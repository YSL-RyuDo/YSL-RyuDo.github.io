A Comparative Analysis of Software Component Provenance Identification Techniques

Compared CENTRIS, BinaryAI, LibAM, BinCoFer and BLADE through their inputs, matching evidence and outputs. Analyzed how shared dependencies, partial reuse and missing references limit source attribution.

Organized the comparison around reference coverage, matched locations, alternative explanations and unresolved questions. Component detection, reuse locations and direct provenance require different evidence.

Comparison framework

TechniqueEvidence and outputInterpretation
CENTRISSeparates borrowed code before comparing source functions.Observed project history is not proof of first authorship.
BinaryAIMatches binary functions to source functions using embeddings and structural context.Small reuse fragments and shared dependencies can affect detection.
LibAMMatches similar functions and call-graph regions.A reused region does not by itself identify an exact version.
BinCoFerRefines function features and aggregates weighted similarity.Shared functions can leave original provenance unresolved.
BLADERetrieves candidates and verifies multiple structured evidence sources.Results depend on available evidence and model reliability.

This paper compares five published techniques through a literature analysis. It does not report a new algorithm or a head-to-head benchmark.
